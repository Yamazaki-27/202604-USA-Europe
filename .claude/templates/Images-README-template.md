# このフォルダーの写真の扱い方

レポート・アルバム作成で使う写真を置く場所である。**人間が事前にやること**と**Claudeがやること**を分けてある。守らないとリポジトリが肥大化し、Claudeの処理がProプランの5時間枠で終わらなくなる。

## フォルダー構成

| フォルダー | 中身 | 誰が入れるか | Claudeの扱い |
|---|---|---|---|
| `Gensen/` | **人間が予め厳選した写真** | 人間 | **必ず全て採用する。**間引き・不採用の判断をしない |
| （直下） | 選別前の候補写真 | 人間 | Claudeが採否を判断する。不採用は`unUsed/`か`OtherPictures/`へ |
| `OtherPictures/` | 採用写真とよく似た写真 | Claude | レポート末尾「その他の写真」章に掲載する。**削除しない** |
| `unUsed/` | ピンぼけ・手ブレ・ほぼ同一の重複 | Claude | レポートに一切出さない。**確認不要で削除してよい** |

`Gensen/` に入れた写真は「これは絶対に載せたい」という意思表示である。Claudeは採否を問い直さず、必ず本文に配置する。

## 人間の事前作業（重要）

### 1. 写真は1600px程度に縮小してから置く

原寸（長辺4000px超・数MB）のまま置かない。**1600pxが基準**である。

なぜ1600pxかというと、配布用PDFの画質のためである。A4・余白13mmで本文幅184mm＝7.24インチとなり、全幅で載せた写真は1600pxなら約221dpiで刷れる。1000pxまで落とすと約138dpiとなり、印刷が明らかに眠くなる。

縮小コマンド：

```bash
# macOS（標準のsipsを使う。1600px以下の写真は縮小しない）
for f in *.jpg *.JPG *.jpeg; do
  [ -f "$f" ] || continue
  w=$(sips -g pixelWidth "$f" | awk '/pixelWidth/{print $2}')
  [ -n "$w" ] && [ "$w" -gt 1600 ] && sips -Z 1600 -s formatOptions 75 "$f"
done
```

```bash
# Windows・Linux（ImageMagick）
magick mogrify -resize 1600x1600\> -quality 75 *.jpg
```

- **1600px以下の写真はそのままでよい。**引き伸ばしてはならない（精細さは増えず容量だけ増える）
- スマートフォンから直接送る場合は、共有時に「実際のサイズ」ではなく中サイズを選ぶだけでも効果がある

### トークンの話：Claudeは1600pxを直接読まない

Claudeは画像を28×28pxのパッチ＝視覚トークンに変換して読み、コストは `⌈幅/28⌉ × ⌈高さ/28⌉` で解像度に比例して跳ね上がる。

| 実解像度 | 1枚あたり |
|---|---|
| 4032px（原寸） | 15,552 |
| 1600px | 2,494 |
| 1000px | 972 |

そこでClaudeは、目視の前に**1000pxの一時コピー**を作業用フォルダーに作り、そちらを読む。リポジトリに残るのは1600pxの本体、Claudeが読むのは1000pxのコピー、という二本立てである。PDF生成は機械的な変換で視覚トークンを消費しないため、この分離が成立する。

一時コピーはコミットしない。人間が用意するのは1600pxの本体だけでよい。

### 2. 撮る枚数ではなく、置く枚数を絞る

`Gensen/` に厳選して置くほど、Claudeが見る枚数が減り、処理が速く安く終わる。解像度を下げてもコストは1枚972トークンが下限なので、**最後に効くのは枚数である**。実例として、原寸416枚（826万トークン・118セッション相当）が、60枚への厳選で**1セッションで完結する**規模になる。

## Claudeの処理方法

1. `Gensen/` は全採用。直下の候補は採否を判断し、不採用を `unUsed/`（削除可）か `OtherPictures/`（残す）へ振り分ける
2. 長辺1600pxを超える写真が残っていればリサイズする。**1600px以下には触らない**
3. 目視用の1000pxコピーを作業用フォルダーに作り、そこにバッチ計画を作る：

   ```bash
   python3 .claude/scripts/plan-photo-batches.py "$SCRATCH/view/Images"
   ```

4. **1バッチ＝1回の新しい会話**で目視・キャプション作成を行い、`_batches/batch_state.txt` に進捗を記録する
5. 全バッチ完了後、写真を読まずにサマリー・まとめ章を書く

## コミットの制限

**長辺2000px超または3MB超の画像はコミットできない**（pre-commitフック・CIで機械的に止まる）。引っかかったら上の縮小コマンドを通してからコミットし直すこと。
